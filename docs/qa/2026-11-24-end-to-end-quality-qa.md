## 출처 수집 결과

독립 라이브 어댑터 검사에서 강남맛집, 디너의여왕, 리뷰노트, 클라우드리뷰, 레뷰, 미블, 놀러와체험단, 모블, 아싸뷰, 오마이블로그, 리뷰플레이스는 ID·제목·원본 URL·플랫폼 형식 계약을 통과했다.

- **포블로그**: EC2 IP 기준 `4blog.net` 목록 API가 HTTP 403을 반환했다. 운영 상태도 `EMPTY`다. 데이터가 잘못 파싱된 문제가 아니라 원본의 서버 IP 차단으로 판단한다. 별도 프록시/허용 IP/공식 제휴 경로 검토가 필요하다.
- **링블**: 단독 심층 어댑터 검사는 상세 마감일 보강 때문에 90초 제한을 초과했다. 다만 운영 벌크 수집은 최근 405건 성공 상태다. 기능 중단은 아니지만, 상세 보강을 큐/배치로 분리하거나 페이지 예산을 낮춰 온디맨드 지연을 줄일 필요가 있다.
- **아싸뷰**: 목록에서 확정 마감일을 제공하지 않는 선착순 유형이 있어 목록 기준 마감일은 비어 있다. 임의 날짜를 만들지 않는 현 정책과 일치한다.

## 수집 이슈 조치 및 재검증

### 포블로그 403

목록 API가 모든 EC2 요청에 403을 반환할 때 파서가 오류를 삼키고 빈 배열을 반환하던 문제를 수정했다. 이제 모든 요청이 실패하면 파서는 예외를 전파하고 `crawler-parallel`은 `crawling_logs`에 `FAILED`와 원인 메시지를 기록한다. 마지막 재검증에서 `/api/source-health`에 포블로그 `FAILED`, `HTTP 403`이 정상 반영됐다.

원본 IP 차단 자체는 코드로 우회하지 않았다. 공식 허용 IP, 제휴 API, 또는 포블로그 측 승인된 수집 경로가 확보되기 전에는 마지막 정상 데이터만 기존 만료 정책에 따라 노출된다.

### 링블 상세 보강 지연

링블 목록 최대 405건 각각의 상세 페이지를 같은 수집 작업에서 확인하던 구조를 변경했다. 기존 DB의 마감일은 먼저 복원하고, 마감일이 없는 최신 60건만 인라인으로 보강한다. 개별 공고의 상세 열람은 기존 상세 조회 경로에서 계속 최신화한다.

변경 전 독립 라이브 검증은 90초 제한을 초과했다. 변경 후에는 **14.7초**, 405건, URL·ID·제목·플랫폼·마감일 형식 모두 통과했다.

### 아싸뷰 확정 마감일 미제공

아싸뷰 목록은 선착순 등 일부 공고의 확정 마감일을 제공하지 않는다. 이 값은 빈 값으로 보존하며, 시스템은 임의 날짜를 만들지 않는다. 마지막 관측 후 48시간 노출 정책과 상세 원본 확인 경로를 유지한다.
