# 카테고리 분류 기준

검색 필터의 카테고리는 `src/lib/category_classifier.ts`가 반환하는 표준 키를 사용한다. 출처가 서로 다른 명칭을 쓰더라도 제목, 혜택, 원본 카테고리를 함께 판단해 같은 키로 저장한다.

## v2 분류 원칙과 저장값

카테고리는 단일 문자열이 아니라 다음 네 가지 정보로 관리한다.

- `sourceCategory`: 출처가 실제로 공개한 원본 카테고리. 덮어쓰지 않는다.
- `category`: 검색에 사용하는 Viral-Re 표준 카테고리.
- `categoryEvidence`: `source-category`, `detail-text`, `list-text`, `title`, `unclassified`, `legacy` 중 판정 근거.
- `categoryConfidence`: `high`, `medium`, `low`, `none` 신뢰도와 `categoryRuleVersion`.

우선순위는 **구체적인 출처 카테고리 > 상세/API 텍스트 > 목록 텍스트 > 제목 > 기타**다. 출처가 `맛집`·`뷰티`처럼 넓은 값만 주는 경우에는 세부 한식·피부처럼 억지로 확정하지 않고 상세·제목 근거로 보완한다.

예: 레뷰 API의 `맛집 > 중식`은 `food-chinese / source-category / high`로 저장한다. 반면 제목만 있는 `봉곡대구막창`은 `food-meat / title / low`로 저장해 후속 상세 수집과 QA의 우선 대상이 된다.

## 계층과 검색 범위

- 상위 `음식`은 한식·양식·일식·중식·카페·주점·분식·육류/구이·오마카세를 모두 포함한다.
- 건강·의료는 병원·치과·한의원처럼 의료 근거가 있을 때만 `병원/의료`로 분류한다. 사주·타로·작명은 별도 `사주/타로`다.
- 세부 항목은 자신의 키만 조회한다. 예를 들어 `육류/구이`를 고르면 일반 한식 전체가 섞이지 않는다.
- `기타`는 원본에 신뢰할 만한 분류 근거가 없는 경우만 사용한다. 기존 `general` 값도 기타에 포함해 누락을 막는다.

## 우선순위

1. 출처가 공개한 구체적인 원본 카테고리
2. 상세/API의 업종·상품·제공 혜택
3. 목록의 설명
4. 제목의 명시적인 업종 신호(오마카세, 마라탕, 한우, 떡볶이 등)

`체험`, `체험권` 단독은 분류 근거로 쓰지 않는다. `식사권`은 음식점임을 보이지만, 한·중·일식처럼 세부 요리를 추정하지 않고 `한식/맛집`으로만 분류한다.

## 변경 절차

새 키를 추가할 때는 `category_classifier.ts`, `CATEGORY_GROUP_MAP`, 화면 라벨, 회귀 테스트를 함께 수정한다. `npm run reclassify:categories:v2`는 활성 공고의 변경 예상치와 근거 분포만 출력하는 dry-run이며, 결과 검토 뒤에만 `npm run reclassify:categories:v2 -- --apply`를 실행한다. 출처가 준 구체 카테고리는 이 스크립트로 일괄 덮어쓰지 않는다.

## 출처별 보강 순서

| 우선 | 출처 | 현재 근거 | 다음 보강 |
| --- | --- | --- | --- |
| 1 | 레뷰 | API 원본 카테고리 + 혜택 | 원본 배열 보존 및 직접 매핑 |
| 2 | 클라우드리뷰 | 목록의 `[식품]`·`[생활]`·`[패션]` 등 태그 | 태그는 보존, 넓은 `뷰티`는 상세 텍스트로만 세분화 |
| 3 | 디너의여왕 | 목록 + 상세 제공내역 | 상세 제공내역으로 `detail-text/high` 재분류 |
| 4 | 아싸뷰 | 목록 + 제한적 상세 키워드 | `분유`, `니플패치`, `면도`처럼 단일 업종이 확실한 신호만 반영 |
| 5 | 리뷰플레이스 | 제목, 상세 제공혜택 | 상세의 업종/태그 파서 추가 |
| 6 | 링블·모블 등 | 제목 중심인 구간 존재 | 각 상세의 공개 카테고리/배지 DOM을 fixture로 확인 후 추가 |

출처별 파서를 추가할 때에는 실제 원본값, 표준 키, 근거 수준을 fixture로 남긴다. 단순 키워드 추가로 기존 공고를 재분류하지 않는다.

### 아싸뷰 SEO 키워드 오분류 방지

아싸뷰 상세의 `본문 키워드`는 포스팅 SEO용이므로, 예를 들어 빨래집게 공고에 `여행`이 들어갈 수 있다. 따라서 전체 키워드를 범용 분류기에 넘기면 안 된다. 현재는 `분유/신생아`, `니플패치/브라`, `면도/쉐이빙`, 반려동물, 영양제처럼 해당 카테고리를 단독으로 입증하는 신호만 `detail-text/high`로 승격한다. 나머지는 `기타`에 남겨 별도 원본 카테고리 파서 대상이 된다.
