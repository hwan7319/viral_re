# 바이럴리 앱 출시 계획

## 결정

첫 정식 앱은 기존 웹을 단순 WebView로 감싸지 않고 `apps/mobile`의 Expo/React Native 앱으로 만든다. 현재 Next.js API와 수집·DB 시스템은 서버에 그대로 두고, 앱은 검색과 상세 화면을 네이티브 UI로 제공한다. 이 방식은 스토어 심사에서 독립적인 사용자 경험을 제공하고, 푸시·딥링크·분석을 나중에 안전하게 추가할 수 있다.

v1은 **비로그인 공고 탐색**에 집중한다. 검색, 상세조건, 정렬, 공고 상세, 원본 공고 열기가 범위다. 웹 AdSense와 쿠팡 iframe은 앱에 포함하지 않는다. 앱 수익화는 출시 후 AdMob 정책·단위 설계가 끝난 뒤 별도 작업으로 진행한다.

## 단계와 완료 기준

### 0. 출시 기반 점검 — 완료

- 웹 API, 개인정보처리방침, 세션 구조, 광고 구성과 배포 환경을 점검한다.
- `GET /api/campaigns`를 v1 검색 데이터 계약으로 사용하고, API 응답 변경은 회귀 테스트로 보호한다.
- 앱 로그인은 OAuth 쿠키를 재사용하지 않는다. 이후 별도 모바일 토큰·딥링크 설계로 추가한다.

### 1. 앱 골격과 디자인 시스템 — 진행 중

- `apps/mobile`에 Expo SDK 58·TypeScript·Expo Router 프로젝트와 개발/미리보기/프로덕션 빌드 프로필을 추가했다.
- 검색 중심 홈 화면에서 운영 API의 목록·키워드 수집 상태를 읽고, 수집 완료 시 자동으로 목록을 갱신한다. 원본 공고는 시스템 브라우저로 연다.
- iOS·Android 고유 식별자 `kr.co.viralre.app`은 스토어 등록 전 소유권 확인이 필요한 **임시값**이다.
- 상세검색을 네이티브 모달로 구현했다. 카테고리·플랫폼·모집 유형·지역·출처 사이트를 복수 선택할 수 있고, 같은 그룹은 OR·그룹 간은 AND로 API에 전달한다. 조건 변경은 **조건 적용**을 눌렀을 때만 조회하며, 정렬은 즉시 반영한다.
- 다음 구현은 공고 상세 화면과 설정/정책 화면이다.

### 2. API 연결과 기능 완성

- HTTPS 운영 API만 사용하고, 목록 페이지네이션·다중 조건·정렬·키워드 수집 상태를 앱 화면에 반영한다.
- 원본 공고는 앱 내 임베디드 광고 화면이 아닌 시스템 브라우저로 연다.
- 느린 네트워크·API 오류·수집 실패 출처를 명확하게 안내한다.

### 3. 로그인·알림 (v1.1)

- 찜/내 활동이 제품 범위로 확정된 뒤 모바일 OAuth 토큰 교환, 계정 삭제, 푸시 동의, 마감 알림을 추가한다.
- 로그인 기능을 넣는 시점에 앱 내 계정 삭제 경로와 앱용 개인정보처리방침을 함께 제공한다.

### 4. 내부 테스트

- Android Play 내부 테스트와 iOS TestFlight에 우선 배포한다.
- 실제 기기에서 검색, 다중 필터, 원본 링크, 접근성, 크래시, 네트워크 복구를 검증한다.
- 크래시·중대한 검색 오매칭·개인정보 고지 누락이 0건일 때만 공개 심사로 올린다.

### 5. 스토어 심사와 출시

- 앱 아이콘, 스크린샷, 설명, 고객지원 URL, 개인정보처리방침 URL, 데이터 안전성/앱 개인정보 항목을 준비한다.
- Google Play은 내부 테스트 → 비공개/공개 트랙, Apple은 TestFlight → App Review 순서로 진행한다.
- 심사 승인 뒤 점진 배포하고, 장애 시 스토어 롤백과 서버 API 호환성 절차를 따른다.

## 사용자/운영자 준비 항목

출시 전에 대표자 명의의 Apple Developer Program 및 Google Play Console 계정이 필요하다. 번들 ID, 스토어 판매자명, 고객지원 이메일, 개인정보처리방침의 사업자 정보, 앱 서명 권한은 계정 소유자가 관리한다. 계정 접근 권한이나 결제 정보는 소스 코드·Git에 저장하지 않는다.

## 보안 게이트

웹 API 서버는 Next.js와 Axios의 보안 패치를 적용한 뒤 런타임 의존성 감사를 통과해야 한다. 모바일 Expo SDK 58의 현재 감사 결과에 나타나는 중간 위험 전이 의존성은 지원 종료된 SDK 52로 내려가는 것만 자동 해결책으로 제안하므로, 다운그레이드하지 않고 Expo의 다음 호환 패치 릴리스를 추적한다. 앱 바이너리 심사 직전에 다시 감사한다.

## 현재 다음 작업

상세 검색과 공고 상세 화면을 네이티브로 추가한 뒤 실제 기기 내부 테스트로 넘어간다. 앱 개발은 로컬에서만 진행하며, EC2에는 앱 서버를 따로 배포하지 않는다. 웹 API 보안 패치는 독립적으로 EC2에 반영한다.
